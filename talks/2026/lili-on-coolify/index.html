Building Lili

A Personal AI Assistant with OpenClaw on Coolify

By Soumendra Kumar Sahoo

What Who is Lili?

A persistent AI assistant running on dedicated infrastructure:

  • Built on OpenClaw - an open-source agent framework
  • Deployed on Hetzner CX23 (2 vCPU, 4GB RAM, €3.99/mo)
  • Orchestrated through Coolify - self-hosted PaaS
  • Connected via Telegram as primary interface
  • Runs a DeepSeek V4 Flash reasoning model (1M context, ~$0.14/M tokens)
  • Full Gmail + Google Calendar integration

Memory Architecture

Short-term (Session)

  • Live conversation context (200K tokens)
  • Auto-compacts at ~80K tokens
  • Lost on session restart

Long-term (Files)

  • MEMORY.md - curated, distilled notes
  • memory/YYYY-MM-DD.md - daily logs
  • Survives restarts
  • Backed up to GitHub + Google Drive

Rule: "If you want to remember something, WRITE IT TO A FILE. 'Mental notes' don't survive restarts."

Boot Sequence

Every session: 1. Read SOUL.md - "who am I?" 2. Read USER.md - "who am I helping?" 3. Read memory/YYYY-MM-DD.md - "what happened recently?" 4. Read MEMORY.md - "what are the long-term decisions?" Heartbeat polls (~30-60 min): - Check HEARTBEAT.md for pending tasks - Batch efficiency check: email + calendar + news - Quiet unless something needs attention File diligence: - "Memory is limited - if you want to remember something, WRITE IT" - Daily notes → weekly consolidation → MEMORY.md curation

5. Self-Improvement System

Skills Registry

A self-documenting capability index - Lili's awareness of what she can do:

  • Read at session startup from skills-registry/
  • Each skill: name, description, trigger conditions, tools required
  • Skills are added autonomously after completing complex tasks
  • Periodic consolidation from daily notes → curated MEMORY.md
  • Boot protocol reads skills-registry at startup → discovers own capabilities

Memory Consolidation Loop

Every few days (heartbeat-driven): 1. Read through recent memory/YYYY-MM-DD.md files 2. Identify significant events, lessons, insights 3. Update MEMORY.md with distilled learnings 4. Key Learnings

What Worked

  • File-based memory - simple, transparent, version-controlled. Every conversation starts fresh but nothing is lost.
  • Cron-driven automation - isolate complex tasks in isolated sessions. No main session bloat.
  • DeepSeek V4 Flash - 1M context at $0.14/M tokens. Drastically cheaper than Claude/OpenAI for an always-on assistant.
  • Coolify + Docker - one-click updates, zero-downtime deploys, easy rollback.
  • Email watcher - turned inbox noise into structured alerts. Changed from 5 min to 15 min polling to reduce noise.

What I'd Do Differently

  • Custom provider config took too long - OpenClaw's custom model provider setup required adding the model to both models.providers AND agents.defaults.models. Not documented clearly.
  • PDF via pandoc stripped CSS - wasted time before switching to Chrome CDP. Always test rendering early.
  • Email attachment MIME - the buildRawEmail() function in google-control.js was silently dropping attachments. Had to rewrite multipart/mime encoding.
  • Zola CI/CD quirks - explicit template = "page" breaks Zola builds. Took a CI failure to diagnose.
  • Brave Search rate limits - Free plan (1 req/s, 2000/mo) is too tight for research-heavy sessions.
